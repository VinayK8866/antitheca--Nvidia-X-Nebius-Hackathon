# AntiTheca Epistemic Guard Skill for Hermes Agent

## Purpose
By default, autonomous agents (like Hermes) are eager to execute user commands without questioning historical context.
For example, if a user tells Hermes:
> *"Refactor our payment backend into 15 microservices with Apache Kafka."*

Hermes might immediately scaffold 15 Dockerfiles and a Kafka cluster—completely oblivious to the fact that two weeks ago the team committed to **ADR 028: Lean Monolith Mandate**.

This skill gives Hermes **epistemic sovereignty and zero-sycophancy guardrails**:
Before generating code or executing destructive architectural modifications, Hermes calls `antitheca_audit_decision` or `antitheca_search_memory` to check for contradictions against the user's sovereign vault.

## Available Tools

### 1. `antitheca_audit_decision(proposal: str, context: Optional[str])`
- **When to use:** Whenever the user proposes an architectural shift, a new library, or a system refactor.
- **Output:** Returns detected epistemic tensions, conflicting ADR IDs (e.g. `ADR-028`), and contrarian counter-arguments generated by NVIDIA Nemotron 3 Ultra 550B.
- **Action:** If `tension_detected` is `true`, Hermes MUST pause and confront the user with the contradiction rather than blindly generating code.

### 2. `antitheca_search_memory(query: str)`
- **When to use:** When Hermes needs to retrieve the user's personal principles, past ADRs, or consolidated notes from `self_brain.db`.

### 3. `antitheca_record_atom(title: str, content: str, tags: List[str])`
- **When to use:** When Hermes makes a new architectural decision with the user and needs to commit it permanently into the sovereign vault.
